**وب‌اپ فارسی و راست‌به‌چپ، با فونت Vazirmatn، بدون رمز یا سرور شخصی، قابل اجرا روی GitHub Pages.**

این سایت سه لایهٔ شفاف دارد:

- **میوز / فاز C4**: ده قاعدهٔ اولیه و ۳۴ نقل کوتاه با شناسه کانونی
- **Codex / پژوهش Step 1**: ممیزی ماشینی ده قاعده، ۶۰ نظر درباره اجزا، صورت اصلاحی، دلیل و ارجاع به سیاق ۵۸ رکورد متن
- **شما / پژوهشگر اصلی**: رأی انسانیِ مستقل درباره اصلاح‌های پیشنهادی، تأیید/رد/اصلاح/تعلیق و ثبت استدلال

**مهم:** نتیجه Codex هرگز به صورت خودکار به عنوان نظر شما ثبت نمی‌شود. تمامی قواعد همچنان پژوهشی و خارج از موتور تاریخی هستند.

## روش صحیح داوری

۱. در بالای صفحه **نام پژوهشگر** را وارد کنید. چاپ مورد بررسی را فقط اگر واقعاً با آن مقابله کرده‌اید مشخص کنید.

۲. از سمت راست یک پرونده انتخاب کنید؛ پیشنهاد اولیه سایت «وحدت موضوع در تحقق تعارض» است.

۳. **گام ۱ ـ ادعای اولیه:** ببینید میوز چه ضابطه‌ای به شیخ انصاری نسبت داده و پشتوانه کوتاه C4 چیست.

۴. **گام ۲ ـ نقد Codex:** ابتدا تحلیل و رأی مقدماتی Codex را بخوانید. سپس «صورت اصلاح‌شده پیشنهادی» و دلیل آن را با صورت اولیه مقایسه کنید. جدول ۶ جزء و ارجاعات افزوده در همین صفحه قرار دارد. دکمه‌های ارجاع مانند 12228:1043 متن گسترده‌تر همان رکورد را از EVIDENCE_CONTEXTS.md باز می‌کنند. عبارت‌های منتشرشده **متن دیتابیس** هستند، نه تصویر نسخه چاپی.

۵. **گام ۳ ـ داوری انسانی:** هر شش محور را جداگانه بررسی کنید. نظر Codex، دلیل و لینک‌های رکوردی مرتبط با همان محور نمایش داده می‌شود. در پرتو متن و نقد، درباره خود آن جزء **تأیید / رد / اصلاح / تعلیق** بدهید. برای **تمام انتخاب‌ها حتی تأیید** باید دست‌کم ۱۲ نویسه دلیل مستقل نوشته شود؛ این صرفاً حداقل فنی است و دلیل علمی مختصرِ بی‌محتوا را معتبر نمی‌سازد.

۶. **گام ۴ ـ رأی نهایی:** در این نسخه، رأی شما **درباره صورت اصلاح‌شده پیشنهادی Codex** است، نه موافقت خودکار با رأی Codex و نه رأی اولیه میوز. با استدلال توضیح دهید کدام تقریر را قابل انتساب و تعمیم می‌دانید، کدام قید باید اضافه شود و اگر اختلاف دارید، علت آن چیست. پس از ثبت نهایی، قاعده بعدی را بررسی کنید.

۷. از «دریافت نتیجه‌ها» فایل JSON را دانلود و در گفت‌وگوی ChatGPT ارسال کنید. **ارسال مستقیم از GitHub Pages وجود ندارد.** گزارش Markdown نیز برای مطالعه انسانی قابل دانلود است. خروجی شامل هر دو **تحلیل Codex** و **رأی مستقل شما** با برچسب منشأ آنهاست.

## اعتبارسنجی و محدودیت‌های Step 1

- research/step1/FINDINGS.json شامل ۱۰ پیشنهاد اصلاح‌شده و رأی درباره ۶۰ جزء است، با نام داور: «Codex — ممیزی متنی ماشینی».
- research/step1/EVIDENCE_CONTEXTS.md شامل ۵۸ رکورد سیاق است؛ هر ۵۱ ارجاع متمایز نتایج در این ۵۸ رکورد قابل پیدا کردن است.
- کنترل ۳۴ برش نقل، صفحه دیتابیس، span، هش عبارت و سیاق کوتاه در گزارش Step 1 موفق اعلام شده است.
- **ناسازگاری حل‌نشده:** VERIFICATION.json در ۳۴ مورد recordHashMatches:false دارد، با اینکه VERIFICATION_SUMMARY.json می‌گوید all_exact_checks_pass:true. گزارش فنی باید این دو را به‌صورت معنایی و با تعریف دقیق کنترل‌ها آشتی دهد. وب‌اپ این مغایرت را پنهان نمی‌کند.
- برای CE-01، CE-05 و CE-06 متن کامل پرونده مخالف منتشر نشده است؛ موارد باقیمانده نباید رفع‌شده فرض شوند.
- شناسنامه چاپ از متن دیجیتال پیشنهاد شده، ولی **مقابله با تصویر نسخه چاپ** انجام نشده است.
- این سایت نه ادعای داوری علمی مستقل شخص دیگر دارد و نه هیچ قاعده‌ای را به موتور تاریخی منتقل می‌کند.

## حفظ اطلاعات و نسخه قبلی

ثبت نظرهای شما تنها در localStorage همین مرورگر انجام می‌شود، نه GitHub. کلید ذخیره‌سازی و ساختار اصلی JSON **با نسخه قبلی یکسان** مانده‌اند. یادداشت‌های موجود حفظ می‌شوند؛ چون در این نسخه برای تمام ۶ جزء دلیل لازم است، یک پاسخ قدیمیِ تأیید بدون دلیل ممکن است «ناتمام» نمایش داده شود، اما متن آن حذف نمی‌شود.

برای انتقال به مرورگر یا دستگاه جدید از خروجی JSON و گزینه «ورود فایل پشتیبان JSON» استفاده کنید. در دستگاه‌های عمومی یا مشترک داوری نکنید.

## توسعه و بررسی

اجرای محلی از ریشهٔ مخزن:

    python -m http.server 8080

در نشانی http://localhost:8080 باز کنید.

آزمون‌ها:

    node --check app.js
    node tests/smoke.mjs
    node tests/step1-integration.mjs

مخزن استاتیک و **عمومی** است. پرونده‌های پژوهشی و سیاق‌های کتابی موجود در مخزن برای دیگران قابل دریافت‌اند؛ یادداشت‌های محلی مرورگر در مخزن منتشر نمی‌شوند.
