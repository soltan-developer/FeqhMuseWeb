# فقه میوز · میز داوری علمی شیخ انصاری

**نسخه ساده و راهنمایی‌شده برای GitHub Pages — بدون رمز، Coolify، Docker یا سرور خصوصی.**

این وب‌اپ به شما کمک می‌کند برداشت‌های پژوهشی میوز از روش اجتهادی شیخ انصاری را با متن، سیاق و دلیل بررسی کنید. طراحی فارسی راست‌به‌چپ و فونت **وزیرمتن (Vazirmatn)** دارد.

## Step 1: ممیزی منابع و ادعاها

ممیزی تفصیلی ۱۰ پرونده، ۶۰ محور داوری و ۳۴ قطعه‌نقل در پوشهٔ
[`research/step1`](research/step1/README.md) ثبت شده است. این بسته شامل گزارش فارسی،
سیاق گستردهٔ منابع، یافته‌های ساخت‌یافته، snapshot دادهٔ سایت، نتایج تطبیق فنی و
اسکریپت بازتولید بررسی روی کتاب‌های محلی است.

خلاصهٔ نتیجه: همهٔ نقل‌ها از نظر فنی با منابع محلی تطبیق داشتند، اما چند اتصال
ادعا به شاهد، چند سطح پشتیبانی و بعضی قیود علمی نیازمند اصلاح‌اند. جزئیات و دلیل
هر حکم در [`REPORT_FA.md`](research/step1/REPORT_FA.md) آمده است.

## از کجا شروع کنم؟

پس از باز کردن سایت:

۱. **نام خود را وارد کنید**؛ مشخصات چاپ را فقط اگر واقعاً بررسی کرده‌اید بنویسید.

۲. از فهرست سمت راست، پرونده نخست **«وحدت موضوع در تحقق تعارض»** را انتخاب کنید. این قاعده برای آغاز مناسب‌تر است.

۳. **گام «ادعا و شواهد»** را بخوانید: ابتدا صورت‌بندی پیشنهادی پژوهش و سه سؤال کلیدی نشان داده می‌شود. سپس چند نقل کوتاه از متن شیخ همراه رکورد و صفحه دیتابیس خواهید دید. این‌ها **نقل‌های کوتاه** هستند، نه جایگزین مطالعه صفحه کامل کتاب.

۴. روی **«شروع داوری این قاعده»** بزنید. شش پرسش را یکی‌یکی پاسخ دهید. متن مرتبط هر پرسش در کنار سؤال آمده است. در هر مرحله از بین چهار انتخاب «تأیید»، «رد»، «نیازمند اصلاح» یا «فعلاً معلق» یکی را انتخاب کنید و استدلال بنویسید. اگر تحقیق کافی ندارید، تعلیق را انتخاب کنید؛ لازم نیست به‌زور نظر قطعی بدهید.

۵. در **گام «رأی نهایی»** تصمیم کلی خود را ثبت کنید. این تصمیم مستقل از داوری جزءبه‌جزء است و توضیح مستدل می‌خواهد.

۶. پس از ارزیابی پرونده‌ها، از بالای سایت **«دریافت نتیجه‌ها»** را بزنید و فایل **JSON** را در گفت‌وگوی ChatGPT پیوست کنید تا فاز بعد پروژه را روی نظرات شما بنا کنیم.

نتایج و پیشرفت‌ها در همین مرورگر و با کلید ذخیره‌سازی نسخه قبل ذخیره می‌شوند؛ یادداشت‌های قبلی و خروجی JSON قدیمی همین نسخه می‌توانند بازگردانی شوند. برای حفظ طولانی‌مدت مرتب پشتیبان JSON بگیرید.

## انتشار

برای GitHub Pages: **Settings → Pages → Deploy from a branch** و انتخاب **main** و **/(root)**.

نشانی مورد انتظار پس از انتشار:

https://soltan-developer.github.io/FeqhMuseWeb/

نیازی به سرور جداگانه نیست. برای توسعه محلی نیز:

    python -m http.server 8080

و سپس http://localhost:8080 را باز کنید.

فونت Vazirmatn از Google Fonts بارگذاری می‌شود. اگر آن سرویس مسدود باشد، سایت با فونت‌های جایگزین دستگاه کار می‌کند.

## وضعیت علمی و محرمانگی

- ادعاهای کلیدی هر قاعده **صورت‌بندی راهنمای داوری** هستند، نه متن لفظی شیخ.
- همه ده نامزد و سی‌وچهار شاهد از بسته C4 نگه داشته شده‌اند. شناسنامهٔ نسخه‌های دیجیتال در Step 1 بازیابی شده، اما مقابلهٔ صفحه‌به‌صفحه با تصویر چاپ هنوز انجام نشده است.
- وجود متن در یک رکورد یا تکمیل فرم **اثبات صحت قاعده، استقلال شاهد یا اعتبار تاریخی موتور نیست**.
- انتخاب «تأیید» فقط رأی شما را در مرورگر ثبت می‌کند و هیچ قاعده‌ای را به‌طور خودکار وارد موتور نمی‌کند.
- سایت و مخزن GitHub Pages **عمومی** هستند و رمز ورود ندارند. محتوای کد و داده‌های پژوهشی درج‌شده در مخزن عمومی‌اند. **پاسخ‌های شما** به GitHub ارسال نمی‌شوند؛ آنها در حافظه مرورگرتان ذخیره می‌شوند. روی دستگاه مشترک از آن استفاده نکنید.
