# FeqhMuseWeb — میز داوری اجتهاد (نسخه قابل‌استقرار خصوصی)

وب‌اپ راست‌به‌چپ داوری ۱۰ قاعده و ۳۴ شاهد کانونی Phase C4. این پروژه علاوه بر رابط مرورگر، **سرور Node.js با احراز هویت واقعی و رمز عبور** دارد.

## هشدار امنیتی ـ فوراً این دو کار را انجام دهید

این مخزن **در ابتدا عمومی بوده و فایل دادهٔ علمی در نسخه‌های منتشرشده و تاریخچه Git قابل دسترسی است**. سرور رمزدار، نشانی GitHub Pages یا GitHub repository را از کار نمی‌اندازد. بنابراین پیش از واردکردن اطلاعات محرمانه‌تر:

۱. در GitHub وارد **Settings → Pages** شوید و با گزینه **Unpublish site** سایت قبلی را از انتشار خارج کنید. در صورت لزوم **Build and deployment → Deploy from a branch → Branch: None → Save** را انتخاب کنید. صرف حذف فایل workflow به معنی لغو انتشار فعلی نیست.
۲. در **Settings → General → Danger Zone → Change repository visibility → Make private**، مخزن را خصوصی کنید. این تغییر برای جلوگیری از دسترسی‌های بعدی لازم است؛ داده‌ای که قبلاً عمومی بوده ممکن است کپی یا کش شده باشد. اگر محرمانگی کامل منابع ضروری است، از یک مخزن خصوصی تازه با تاریخچه تمیز استفاده کنید.
۳. **GitHub Pages را دوباره فعال نکنید.** Pages در مخزن شخصی، سیستم رمز عبور سمت سرور را اجرا نمی‌کند و ممکن است حتی برای مخزن خصوصی نیز عمومی باشد.
۴. نسخه سروری پایین را روی **Coolify** یا یک سرویس Node/Docker مجهز به HTTPS راه‌اندازی کنید.

**تا انجام این مراحل، نمی‌توان دسترسی را «فقط مخصوص صاحب سایت» دانست.**

## راه‌اندازی در Coolify

- از یک پروژه Coolify، یک **Application** جدید از مخزن GitHub \`soltan-developer/FeqhMuseWeb\` بسازید. اگر مخزن خصوصی شده، GitHub integration را برای آن مجاز کنید.
- Build Pack را **Dockerfile** انتخاب کنید؛ پورت داخلی: **3000**.
- دامنه‌ای با HTTPS فعال برای اپ تعریف کنید. در محیط Production، برنامه فقط درخواست‌های HTTPS را می‌پذیرد.
- Environment Variables (به‌صورت **Secret** یا مقدار محرمانه) را تنظیم کنید:

| متغیر | مقدار |
|---|---|
| \`FEQH_AUTH_USERNAME\` | یک نام کاربری دلخواه، مثلاً \`scholar\` |
| \`FEQH_AUTH_PASSWORD\` | گذرواژه **منحصربه‌فرد و طولانی، حداقل ۱۶ کاراکتر** |
| \`PORT\` | \`3000\` |
| \`FEQH_HOST\` | \`0.0.0.0\` |
| \`FEQH_TRUST_PROXY\` | \`1\` |
| \`FEQH_ALLOW_HTTP_DEV\` | \`0\` |

- با **Deploy** برنامه را بالا بیاورید. سرور، رمز عبور را در فایل‌ها یا JavaScript عمومی قرار نمی‌دهد. توکن تصادفی ورود از کوکی Secure/HttpOnly با SameSite=Strict استفاده می‌کند و هشت ساعت اعتبار دارد.
- **هیچ پورت 3000 مستقیمی را عمومی نکنید**؛ تنها پراکسی HTTPS مجاز به دسترسی به کانتینر باشد.
- از گزینه «خروج امن» در نوار بالای برنامه برای بستن نشست استفاده کنید.

رمز را **در چت، Issue، مخزن GitHub، کد یا README قرار ندهید**. مقدار نمونه \`.env.example\` یک placeholder است و سرور عمداً آن را نمی‌پذیرد. رمز خودتان را فقط در تنظیمات محرمانه Coolify ثبت کنید.

## آزمون ورود و ممنوعیت دسترسی مستقیم

این برنامه بدون هیچ بسته شخص ثالثی کار می‌کند:

    node --check server.mjs
    node tests/auth.mjs
    node tests/smoke.mjs

آزمون‌ها شامل رد درخواست مستقیم JSON، حفاظت از JS/CSS، محدودیت تلاش ناموفق، ایجاد و ابطال کوکی نشست، و جلوگیری از ارائه فایل‌های خارج از allowlist هستند.

## اجرای محلی فقط برای توسعه

برای آزمایش روی **همان کامپیوتر شخصی** می‌توانید با متغیرهای محلی زیر اجرا کنید:

    FEQH_AUTH_USERNAME=scholar FEQH_AUTH_PASSWORD="SET_A_NEW_LONG_RANDOM_DEV_PASSWORD_123" FEQH_ALLOW_HTTP_DEV=1 FEQH_HOST=127.0.0.1 PORT=3000 node server.mjs

نمونه بالا فقط نمایشی است؛ برای استفاده واقعی گذرواژه یکتای خودتان را قرار دهید. آدرس توسعه: http://127.0.0.1:3000 .

## حریم خصوصی داوری

نظرهای شما همچنان در localStorage مرورگر ذخیره می‌شوند، برای انتقال باید **خروجی JSON** بگیرید و در همین گفت‌وگو پیوست کنید. این حافظه رمزنگاری‌شده نیست؛ از دستگاه مشترک استفاده نکنید و نسخه پشتیبان منظم تهیه کنید.

- تأیید شما در سایت «خودداوری پژوهشگر اصلی» است و صلاحیت علمی مستقل محسوب نمی‌شود.
- هر ده قاعده در وضعیت پژوهشی و غیرقابل اجرای تاریخی باقی می‌مانند.
- سه چاپ هنوز \`PRINT_EDITION_UNKNOWN\` هستند.
- به‌دلیل عمومی‌بودن قبلی تاریخچه، تغییر دسترسی فعلی هرگز افشای گذشته را خنثی نمی‌کند.

**سرور رمزدار فقط دسترسی به استقرار جدید را کنترل می‌کند؛ محرمانگی منبع GitHub، تاریخچه قبلی و دامنه Pages باید جداگانه اصلاح شود.**
